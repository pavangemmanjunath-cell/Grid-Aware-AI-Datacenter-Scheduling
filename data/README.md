# Dataset documentation

## Dataset name

**QH2DC 168-hour benchmark** — `research_benchmark_168h.csv` and the derived bundle table
`research_flexible_jobs.csv`.

## Purpose

A controlled, fully inspectable test week on which the connection-capacity question can be answered and
reproduced exactly: one hourly table that joins AI demand, on-site generation, grid carbon intensity and
two connection envelopes. It supports claims about the **mechanism** (which resource relieves which
hours), not about the absolute megawatts of any real data centre.

## Source and type

| | |
|---|---|
| Type | **Synthetic / simulated.** Not operator data, not a replay of any public trace |
| Generator | `matlab/qh2dc_build_benchmark.m`, seed `cfg.rng_seed = 20260430` (`matlab/qh2dc_config.m`) |
| Original URL | This repository |
| Licence | Apache-2.0, as the rest of the repository |
| Redistribution | Permitted; the data were generated by the authors and contain no third-party or personal data |

Why synthetic: no public dataset carries GPU workload, on-site solar and wind, grid carbon intensity and
a time-varying connection envelope **for the same site and week**. Joining four unrelated real sources
would be no less synthetic, only with the seams hidden. A seeded generator makes every signal inspectable,
lets the hydrogen plant be deliberately undersized, and lets the envelope bind in a controlled way.

## Schema — `research_flexible_jobs.csv`

`job_id`, `day`, `baseline_hour`, `energy_MWh`, `cand_1`, `cand_2`, `cand_3` (baseline, +3 h, +7 h),
`release_h`, `deadline_h`. Each bundle is a one-hour rectangular block whose energy is preserved when moved.

## Units, missing values, preprocessing

All power in MW, energy in MWh, hydrogen in MWh (LHV). There are no missing values. The only
preprocessing is the validation gate in `qh2dc_load_benchmark.m` (and its Python and web-engine
equivalents): 168 rows, `total = fixed + flexible`, `renewable = solar + wind`. There is no
train/validation/test split: the benchmark is an optimisation instance, not a learning dataset.

## How each signal is generated

All formulas from `qh2dc_build_benchmark.m`; `U` uniform, `N` normal, `hod` hour of day.

| Signal | Process | Rationale |
|---|---|---|
| Latency-sensitive demand | `7.15 + 0.55 sin(2π(hod−3)/24) + 0.20 sin(4π·hod/24) + 0.18 N(0,1)` | inference behaves like a block load with a shallow daily ripple |
| Bundles | `5.2 + 2.8 U(0,1)` MW at hod ∈ {6, 8, 11, 14} | discrete blocks make placement a binary decision |
| Solar | `8.6 · max(0, sin(π(hod−6)/12))^1.35 · (0.70 + 0.30 U)`, zero outside 07:00–18:00 | sharpened midday peak coincides with the non-firm window |
| Wind | AR(1): `w ← 0.88 w + 0.12 (2.6 + 2.2 U) + 0.35 N`, clipped to [0.3, 5.0] | persistence creates low-wind evenings, the hours that set the peak |
| Carbon intensity | `470 − 160·solar/max(solar) − 22 (wind − mean) + 14 N`, floor 180 | cleanest hours are sunny ones — exactly when the non-firm cap closes |
| Non-firm envelope | 10.7 MW, 6.5 MW for hod 8–14 inclusive | controlled, deliberately hard scenario |
| Phased envelope | 8.7 → 9.7 → 10.7 MW in three 56-h stages | no deep midday cut; contrasts with non-firm |

Changing the seed produces a different week and **different published numbers**; the seed is part of the result.

## Known biases and limitations

- One week, one synthetic site; not statistically representative of any production week.
- The carbon-intensity range (180–482 kg/MWh) is higher than, for example, Great Britain on 1–8 January
  2025 (35–221 g/kWh, mean 116, according to a one-off query of the NESO Carbon Intensity API on
  2026-11-21 made while documenting this repository; the software itself does not query it). The
  benchmark is not meant to represent a specific grid.
- Solar reaches 8.48 MW and wind 0.86–4.66 MW in the file. These are benchmark outputs, not nameplate
  ratings.
- `qh2dc_ingest_trace.m` (production-trace path) uses workload-to-power coefficients that are optimistic
  (A100-class 400 W GPU, PUE 1.18); recalibrate before quoting absolute MW. It is not exercised by any test.

## Connected datasets: none

This software is connected to **no external dataset and no external API**. It reads only the synthetic
files in this folder, and nothing is downloaded at runtime. The published results do not depend on any
third-party data.

## What may and may not be said about this data

**May be said:** "a deterministic 168-hour simulation benchmark, reproducible from a fixed seed";
"public datasets are listed as external-validation sources"; relative results such as the 41.0 %
reduction on this benchmark.

**May not be said:** "derived from Alibaba / NESO / Renewables.ninja"; "representative of a real AI data
centre's absolute demand"; "72 % electrolyser efficiency is typical" (it is a DOE ultimate target);
"PUE 1.18 is typical".
